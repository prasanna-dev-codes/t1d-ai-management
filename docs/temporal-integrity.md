# Phase 02 temporal integrity

EventRevision separates `event_time` (occurrence), `recorded_at` (source entry), `ingested_at` (server receipt) and `available_at` (server knowledge). The latter two are overwritten by an insert trigger using the database clock, including for backfills. Clients cannot backdate knowledge. Original UTC offset and provenance are retained; PostgreSQL stores aware instants and application sessions use UTC. Response instants are UTC offsets equivalent to Z; callers must compare instants rather than strings.

Naive datetimes, numeric epoch values and numeric timestamp strings are rejected; APIs require explicitly zoned RFC3339 strings. An explicit offset disambiguates repeated daylight-saving clock times; no IANA-zone or local-machine timezone is silently inferred. Sources lacking an unambiguous offset must be normalized by a future authorized adapter and document their reconstruction. Event time ≤ recorded time ≤ server ingestion is required; future events and future recorded times are rejected. Phase 02 `planned` insulin means historical documentation of a plan, never a future administration or evidence of delivery.

All four plain-history GET resources require an aware cutoff no later than now, have limit 1–200 and opaque bounded cursor, and order by `(event_time, UUID)`. The repository first selects revisions with `available_at <= cutoff`, ranks each scoped source/event chain by revision, then excludes latest quarantined or future-event records. It never selects today's latest revision and pretends it was known historically; it never resurrects an older record when a known latest revision is quarantined. Delayed/backfilled observations are invisible before server availability even if their event occurred earlier.

Current grant/consent is required at query time. Historical authorization is not a way to bypass present revocation. Cursors are untrusted position hints: parsing and SQL binding are bounded, and every request reapplies scope, cutoff and visibility. Clients must keep cutoff fixed while paging. Quarantine review/release needs a new reviewed revision; no release endpoint is implemented.

The disposable tests cover delayed/corrected histories, old cutoffs, unavailable revisions, source/device identity, quarantined latest revisions, missing samples, bounded pagination and patient isolation. No forecasting, episode summarization, embeddings, graph edges or feature snapshots exist. Later consumers must enforce task-specific quality eligibility and transformation availability in addition to these event-level queries; this is not evidence of an unbiased forecasting evaluation.

The availability marker is a server acceptance timestamp inside the atomic ingest transaction; uncommitted rows are invisible to concurrent readers. It is not a source-vendor knowledge-time claim or an exact commit timestamp. Later retrospective feature evaluation must pin input snapshots and transformation availability, and document clock/collection assumptions.
