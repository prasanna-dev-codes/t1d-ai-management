# ML research and evaluation plan

Status: Planned experiments only. No models, datasets, benchmark values, or validation claims exist. Dataset approval follows [data strategy](datasets.md). Tier 3 outputs glucose forecasts, never treatment instructions.

## Hypotheses and falsification
- H1: human-corrected multi-food components improve nutrient estimation over image-only classification; reject if held-out error/uncertainty does not improve at feasible review effort.
- H2: patient- and time-bounded episode retrieval improves forecasting over the identical model without retrieval; reject if gains disappear under strict cutoff controls or subgroup errors worsen beyond approved criteria.
- H3: personalization improves eligible within-patient future forecasts relative to population baselines; reject if cold-start or later temporal holdouts fail to improve.
- H4: advanced sequence/physiology-informed models improve at least one prespecified error/calibration criterion without unacceptable subgroup, latency or abstention costs. A negative result is valid; simpler models remain eligible winners.

No numeric clinical superiority margin, target error, interval coverage objective, or performance threshold is approved. Prespecify targets with the research supervisor and qualified clinical reviewer before opening the locked test set; include uncertainty around comparisons and multiplicity handling.

## Shared experimental protocol
Freeze a study protocol, dataset/license manifest, patient/dish split IDs in protected storage, preprocessing version, code revision, feature schema, hardware/software versions, seeds, and metric implementation before training. Fit scaling, imputation, augmentation selection, embedding adaptation and hyperparameters on training/validation only. Include missingness indicators; do not impute treatment parameters. Split once before overlapping-window construction and purge/embargo boundary windows based on maximum lookback plus target horizon and episode outcomes. Evaluate each patient's records only in its allocated generalization split.

Use separate tracks: (1) patient-disjoint generalization with no test-patient adaptation; (2) personalization using only an initial chronological prefix of a held-out patient, with a later validation segment and a strictly future locked test segment. Report that personalized results are no longer zero-shot generalization. Any cross-validation is nested/grouped and temporally valid. Embeddings/retrieval indexes used in evaluation must be built from permitted historical content and an embedding model whose training cutoff is disclosed.

Record failed runs and exclusions. Use multiple seeds for stochastic candidates as resources permit, documenting the count in advance. Report uncertainty across patients/sessions, not only overlapping windows as if independent. Bootstrap or resample patient/session clusters, explain small-cohort limits, and report confidence intervals rather than unsupported significance claims. Lock model selection before final test evaluation; post-test tuning creates a new evaluation cycle.

## Food recognition evaluation
Baseline: simple classifier/transfer-learning configuration and human-review-only reference where feasible. Candidates: EfficientNet-B0 classification, empirically selected segmentation approaches including a verified YOLO implementation. Evaluate classification top-1/top-k accuracy, macro F1, class recall, confusion matrices, unknown-food rejection, and confidence calibration. Segmentation metrics include IoU/Dice and class-wise coverage; specify instance-matching rules before comparing mAP. Group by dish/recipe/session; inspect Indian mixed meals, occlusion, lighting, devices and unseen dishes. Include human correction rate/time and abstention coverage. Photographic classification accuracy does not establish nutrition accuracy.

## Portion and nutrition evaluation
Compare manual/known portions, simple reference lookup, image-only estimates, and optional governed multimodal estimates. Ground truth must come from documented measured/reference portions and nutrient definitions, with measurement uncertainty acknowledged. Report mass MAE in g; carbohydrate/protein/fat MAE in g; energy MAE in kcal; signed bias, absolute-error quantiles and interval coverage/width. Relative errors need zero-denominator rules and should not obscure large absolute errors. Analyze ingredient mapping, portion estimation and nutrient-reference errors separately. Test held-out recipes, raw/cooked ambiguity, hidden ingredients, sauces and mixed dishes. Human correction is evaluated as a separate condition, not mislabeled as fully automatic performance. Experimental FPU requires an approved definition and separate study; never use it to derive treatment.

## Glucose forecasting evaluation
Mandatory baselines: persistence and an explicitly specified linear/statistical model. Compare lag-feature XGBoost, GRU/LSTM, TCN, Transformer and optional physiology-informed hybrids only as budget permits. Evaluate at 30, 60, 90 and 120 minutes with exact target alignment/tolerance rules. Report MAE, RMSE, signed bias and error quantiles per horizon in explicit glucose units. Report per-patient distributions, device/cohort subgroup results where authorized and sufficiently populated, missingness strata, and cold-start performance. Optional clinical error-grid/time-in-range/event analyses require qualified selection, verified reference definitions and explicit limitations; none proves safe dosing.

Forecast intervals must state nominal coverage, construction method and observed coverage/width per horizon/subgroup. Consider residual/quantile models, ensembles, and carefully calibrated conformal methods; temporal dependence and patient shift can invalidate naive coverage assumptions. Fit calibrators on held-out calibration data, never test data. Assess out-of-distribution detection and risk-coverage curves as abstention increases; report metrics on all cases plus eligibility/abstention rates so excluding difficult cases cannot hide error.

## Retrieval and personalization evaluation
Compare structured-only, vector-only, graph-only and combined retrieval with the same authorized candidate pool. Use expert-reviewed episode relevance, precision/recall@k and ranking metrics, along with downstream forecast delta and latency. Add adversarial future outcomes, late annotations, foreign patient IDs, stale embeddings and index outages. Zero unauthorized/temporally ineligible retrieved evidence is a correctness requirement, not a statistical average. Similarity is not a physiological digital twin or causal guarantee.

## Ablations and model selection
Remove meal context, insulin-history features, activity, retrieval, personalized adaptation and uncertainty features one at a time under identical splits. Compare human-confirmed versus inferred nutrition, graph/vector combinations, missingness levels and simple versus advanced architectures. Preserve deterministic safety gates in every candidate; never ablate away required safety controls for a deployable result.

Choose by prespecified horizon accuracy, interval calibration, subgroup/cold-start behavior, failure/abstention coverage, latency, compute budget, auditability and reproducibility. No single aggregate metric wins automatically. Report parameter count, training duration, peak memory and inference cost on declared hardware. Research approval and software/safety checks are separate gates. No model can be promoted on test accuracy alone.

## Experiment tracking and oversight
MLflow or an approved equivalent tracks configs, aggregate metrics, artifact digests and protected manifest references. Do not upload records, images or patient IDs to unrestricted trackers. Publish model cards with intended use, license/source, feature units, training/data cutoffs, preprocessing, subgroup limits, uncertainty method, failure modes and required human oversight. ONNX exports must match reference inference and interval calculations within declared tolerances. Supervisor/qualified review approves research use; no claim of clinical validation follows.
