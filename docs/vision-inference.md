# Phase 03 ephemeral vision inference

The user explicitly approved this bounded synchronous API/testing UI. [ADR 007](decisions/007-ephemeral-vision-and-cloud-training.md) refines the older unimplemented stored-image/job proposal. The code exists; **no evaluated food artifact or live identity provider is configured**. Current authenticated model status is unavailable and analysis returns 503. Positive tests use explicit test-only providers and do not prove real food recognition.

## Transport and authorization

GET `/api/v1/patients/{patient_id}/vision/model` returns `VisionAvailability`. POST `/api/v1/patients/{patient_id}/vision/analyses?task=single_label_classification` accepts **raw bytes**, not multipart/base64/remote URLs, with `Content-Type: image/jpeg` or `image/png` and `X-Study-ID`. Patient/study IDs are explicit UUIDs. Both require the existing trusted principal/current scope/consent; analysis additionally requires researcher/clinician role and a write grant. The default authenticator stays deny-all. No production test-adapter setting is added.

Scope is checked before reading bytes and rechecked after processing before audit/return. Revocation discards the result. Audit transaction failure blocks success. Protected audit records contain only operation/model/result UUIDs, fixed codes, scope and correlation metadata, never image bytes/labels/EXIF/file paths. Existing failure-audit allowlists are reused, with no schema/function/grant migration. No image, job, meal, EventRevision or canonical clinical Prediction is created. Scope-audit metadata remains governed by existing protected audit retention; raw media has no application persistence.

## Resource and image boundaries

One admitted vision operation per **app process**, no waiting queue. Acquire admission before body reading; cap streaming bytes at **8 MiB**, upload reading at **10 seconds**, dimensions at **32–8192 per side** and **16 million pixels**. MIME must match decoded JPEG/PNG. Reject animated, truncated, unsupported-mode and bomb-like inputs. Apply EXIF orientation, composite alpha onto white, convert RGB and create a fresh pixel-only buffer. ICC is not color-managed and yields a warning; acceptance means successful decode, not verified food content/blur/OOD quality.

Decoding and model loading/inference run in a fresh spawned process under a **five-second** supervision deadline and a **1 GiB sampled RSS** threshold. Terminate/kill/join after timeout, cancellation, memory excess or completion. Input transport avoids putting large media in the blocking spawn arguments; a separate bounded pipe feeder remains under supervision. Reply IPC is capped **128 KiB JSON**, never child-to-parent pickle. Native stdout/stderr are suppressed and failures map to fixed codes. ORT CPU threads are limited to one. No persistent image/result cache or downloaded fallback model exists.

The RSS watchdog samples about every 20 ms: it can terminate observed excess but does not provide an instantaneous hard macOS allocation ceiling. Input/pixel caps provide additional deterministic bounds. Process isolation here is a resource boundary, not a hardened OS security sandbox; OS swap/core dumps/browser memory and multiple independently launched API processes are outside an application-level no-persistence guarantee. Public/real-health-data deployment is not authorized. Cold startup/model validation counts toward the inference deadline and may render a future artifact unavailable until measured. No latency guarantee is derived from the chip name.

## Artifact and result contracts

Only explicitly configured `T1D_VISION_ARTIFACT_DIR` absolute local roots are considered. No root is configured by default. A candidate must bind graph/report SHA-256, model UUID/version, dataset/split digests, ordered canonical classes, taxonomy/preprocessing/calibration/code identity and rights/approval references. Reject engineering-only or uncalibrated/unthresholded artifacts for serving; validate report identities and nonzero held-out evidence metadata. These references are trusted-operator attestations, not independent scientific/legal proof or signed model promotion. Require human evidence review before configuring a serving root.

Reject graph path escape/symlinks, oversized metadata/graph files, external tensor data, custom domains/functions, nested control-flow graphs and incompatible input/output shapes/dtypes. Supported interface is fixed float `[1,3,224,224]` to `[1,class_count]`, CPU provider. Only single-label classification is available when a genuine eligible artifact exists. Other task types produce explicit unsupported abstention, not boxes or masks. Evaluation report metadata is not a substitute for the actual empirical review.

`VisionResult` carries prediction UUID, review-required/abstained status, task, opaque model/data/taxonomy/preprocessing versions, decoded image status, ranked canonical alternatives/probabilities, fixed reason codes, processing time and aware completion timestamp. Always `experimental=true` and `review_required=true`. Ranking is not ingredients, instance counting, portion/nutrient estimation or reliable unknown detection. A high maximum softmax score can still be wrong; no OOD reliability is claimed. Human review is required for every label.

Responses reuse the existing safe error envelope: 401 unauthenticated, opaque 404 unavailable scope, 413 bytes exceeded, 415 format/mode unsupported, 422 invalid image/metadata, 408 interrupted/slow upload, 503 unavailable/busy/memory/worker failure and 504 process deadline. No raw decoder exception/path or image echo is returned. There is no production rate limiter or async job lifecycle in this phase.

## Minimal testing UI

`/vision` offers explicit study/patient UUIDs, model status, JPEG/PNG byte/type checks and at most 256 KiB of header inspection for dimension limits before temporary local object-URL preview, loading/error states and only returned classification hypotheses with review/calibration warnings. Preview URLs are revoked on replacement/scope change/unmount; requests abort on unmount and scope controls are locked while pending. No token field, browser credential persistence, development identity bypass, stored image/history, fake overlays or meal confirmation exists. Server error bodies/network internals are not displayed. Default authentication and artifact absence are shown honestly. Frontend mock tests are software checks; genuine end-to-end food output remains BLOCKED.
