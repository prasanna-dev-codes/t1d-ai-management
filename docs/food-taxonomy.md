# Proposed food taxonomy 0.1.0

Status: **PROPOSED, not trainable, not empirically validated**. Machine proposal: [food-taxonomy.v0.1.0.proposed.json](../services/vision/taxonomy/food-taxonomy.v0.1.0.proposed.json). This is a reviewed-scope starting proposal, not an approved final class list or dataset's class ordering.

The 18 concepts are chapati, naan, plain cooked rice, biryani, pulao, fried rice, dal, sambar, chana masala, rajma, idli, dosa, mixed vegetable curry, samosa, chicken curry, poha, upma and omelette. Stable `food.*` IDs have neutral hierarchical parents and human labels preserving unspecified recipe/filling/variety. Spelling aliases are explicit; `roti`, `rice` and `curry` remain ambiguous rather than silently collapsing distinct dishes. Regional names require reviewed justification before being added. This vocabulary says nothing about nutritional equivalence, allergens, ingredients hidden from view or serving mass.

Unknown, unsupported, ambiguous and model-unavailable are **decision states**, not invented trained classes. Model softmax dimensions include only actually trained and evaluated concepts. Top-k alternatives are competing dish identities, not a list of ingredients in a mixed meal.

Each selected source's full taxonomy must be read from an approved release and mapped explicitly before training. Food-101 is optional general benchmark data; this provisional Indian vocabulary is not an exhaustive 101-class mapping. Do not claim idli/dosa/biryani support because those IDs appear in a proposal. Each mapping record will require dataset/release/source-label, canonical ID, mapping rationale, reviewer/status and mapping version. Unmapped or ambiguous concepts fail as unsupported; string similarity cannot choose a nutrient-equivalent label. Broad dish categories can be retained as broad labels without a Phase 04 ingredient/recipe mapping.

Freeze an explicit ordered `{class_index, canonical_id, source_label}` list, taxonomy/mapping/preprocessing versions and content hashes in each model manifest. JSON object/list order and dataset directory enumeration must not silently select logits. Taxonomy changes never reinterpret an existing artifact's output order; incompatible versions require new mapping/evaluation/artifact identity. After acquisition audit, approve the complete vocabulary before promoting this proposal to version 0.1.0.

Run `python3.12 scripts/validate_vision_proposal.py` from the repository root to check IDs/parents/cycles/alias ambiguity, the nine-axis matrix, split roles/fractions and closed acquisition/training/cloud gates (the ephemeral API design is approved). This structural checker proves neither semantic label correctness nor model accuracy. Actual image/mask/mapping validation follows approval and data inspection.
