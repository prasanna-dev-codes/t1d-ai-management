## Candidate baselines and protocol

Compare EfficientNet-B0 and MobileNetV3-Small; do not preselect a winner. The named official `IMAGENET1K_V1` weights are conditionally approved only after provenance, terms and full checksum verification. [B0 official metadata](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.efficientnet_b0.html) and [MobileNet official metadata](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_small.html) describe upstream architectures/weights; upstream performance is not our food accuracy. No pretrained file has been downloaded.

Start seed 42, shared `rgb-letterbox224-v1` preprocessing, 224×224 RGB/NCHW/float32 with ImageNet mean/std. Originals remain untouched. Training-only transformations must preserve labels and groups; deterministic validation/inference reuse the same aspect-preserving letterbox code. Categorical masks need separate joint spatial/nearest-neighbor transforms; classification preprocessing is not mask training.

Proposed AdamW head LR 1e-3/fine-tune LR 1e-4, decay 1e-4, cosine schedule per stage, two frozen-backbone epochs followed by at most eight fine-tune epochs, clipping norm 1, patience 3. Proposed cloud batch 32 is reduced only through recorded measured memory decisions. Use training-only class weights, validation macro-F1 with NLL tie-break, dedicated calibration groups and untouched final test. No search/additional seeds 137/2026 without budget review.

A bounded 20-batch/10-minute pilot per model must precede sustained training. **Twelve hours total maximum**, including setup/pilots, training/validation/calibration/evaluation/export and failed/resumed runs, is a ceiling, never a requested runtime. Stop early for validation convergence or budget; no silent restart resets it. Shared persisted budget ledger, trusted best/last checkpoints, RNG/optimizer/scheduler identity, dataset/split/preprocessing/mapping hashes and restore tests are required of the future trainer. No trainer, GPU/epoch run, checkpoint-resume qualification, real-food calibration or PyTorch export is claimed implemented at this checkpoint.

## Pinned dependencies and actual local scope

`services/vision/pyproject.toml` and `uv.lock` record the base package and optional training extras. Base libraries installed for local inference/software tests: **Pillow 13.0.0** (bounded decode/EXIF/RGB), **NumPy 2.5.4** (preprocessing/metrics), **ONNX 1.23.2** (graph/schema checks), **ONNX Runtime 1.31.1** (CPU inference/parity on authored engineering graph), **psutil 7.2.2** (worker RSS monitoring), and the existing **Pydantic 2.14.2** (typed validation). These do not acquire images or weights. Native M4 CPU tests are evidence only for the exercised paths.

Optional, resolved but **not installed/executed locally**: **Torch 2.15.0**, **Torchvision 0.29.2** and **onnxscript 0.7.2**, for future architecture/training/export qualification. `train-cpu` selects explicit CPU wheels on Linux x64; `train` does not force a CPU build in a GPU cloud host. Cloud driver/Python/wheel/operator compatibility remains unverified. Do not blindly overwrite a provider's working CUDA stack. Base backend/database CI installs no training extras and downloads no food corpus or ImageNet weights. There is no completed optional PyTorch ML job yet.

Publisher metadata identifies Pillow MIT-CMU, NumPy composite BSD/MIT/Zlib/CC0 notices, ONNX Apache-2.0, ORT MIT, psutil BSD-3, onnxscript MIT, Torch composite notices and Torchvision BSD metadata. These are library notices, not blanket rights to pretrained images/weights or our eventual model distribution. Review transitive/bundled notices before distributing artifacts. Native third-party boundaries have scoped mypy overrides; application and vision contracts remain strict.

## Current executable infrastructure and remaining evidence

`images.py` performs bounded decoding/metadata stripping and deterministic letterbox normalization; `datasets.py` produces rights-gated hashes, quality issues, source/duplicate groups, sealed-test-aware splits and box/mask validation; `metrics.py` provides deterministic classification/calibration/risk calculations; `artifacts.py` refuses ineligible/unbound/unsafe graph artifacts; `runtime.py` enforces killable-worker budgets. Handoff scripts inventory allowlisted artifacts and checksums without remote execution or checkpoint loading. Tests use generated pixels and mathematical/reference arrays, not synthetic claims of food accuracy.

Actual training, bootstrap intervals, full-source adapters, robust OOD/challenge evaluation, PyTorch-to-ONNX parity, model selection/threshold empirical evidence and cloud recovery tests remain pending the chosen environment and authorized data. No scikit-learn/MLflow service is added. JSON aggregate experiment tracking and ignored binary artifacts are planned. No patient records, nutrition, portions, insulin or glucose outputs belong in this module.
