# Proposed vision evaluation protocol

Status: **Empirical evaluation NOT RUN; deterministic metric/calibration software tests PASS**. This protocol is part of the Phase 03 approval package, not an evaluation report for an existing model. See [training](vision-training.md) and [dataset assessment](vision-dataset-assessment.md).

Freeze dataset/release/rights evidence, raw hashes, taxonomy/mapping/class-index digest, duplicate/session grouping, train/validation/calibration/test manifests, code/dependency versions and selection criteria before training. Validate group disjointness before image augmentation. Do not use the official or independent final test for stopping, selecting architecture, thresholds, calibration or failure-driven recipe changes. Group provenance gaps must remain visible in the report.

Select by validation macro-F1 with validation NLL tie-break; fit temperature on separate calibration groups. Final metrics: top-1/top-3, macro/weighted F1, per-class precision/recall/support, confusion matrix, NLL, multiclass Brier, ECE with explicit binning and coverage/risk curves. Declare zero-support/zero-denominator handling; missing class coverage must not become a perfect score. Group-bootstrap intervals where justified; disclose small-class/small-sample uncertainty. Record failed/aborted experiments and actual seeds/caps.

Assess approved lighting/blur/angle/occlusion/similar-food/mixed/unseen cases, distinguishing measured natural examples from controlled synthetic corruptions. Unknown rejection requires independent development and sealed evaluation examples; raw softmax is not proof of correctness. All displayed identities require review. A single-dish classifier on a mixed meal does not identify components; report unsupported capability instead of treating top-k as ingredients.

A semantic model, if separately approved/trained, needs per-class IoU/Dice with declared background/void conventions. Detection needs box-matching/AP protocol; instance segmentation needs actual instance identity/matching and mask AP. Neither boxes nor saliency/attention maps are ground-truth masks. Trained detection/segmentation is currently unavailable, with no fabricated metrics.

For evaluated artifacts, compare PyTorch and ONNX logits/probabilities/class order across authorized evaluation samples and synthetic boundary inputs. Declare tolerances and observed maximum drift; exact equality is not assumed. Measure cold/warm CPU, MPS and ORT latency separately; batch size, repeat count, synchronization, thread settings and peak-memory measurement limitations belong in the report. MPS, real-food training/calibration/held-out evaluation and real-model ONNX performance are NOT RUN. An authored tiny ONNX graph matches a NumPy reference on M4 CPU; that is engineering parity, not PyTorch export parity.

The software tests cover taxonomy structure, image/split/annotation validation, hand-calculated classification/calibration metrics, guarded artifact loading, bounded inference, authenticated scoped API behavior and UI states. Group-bootstrap intervals and dataset-specific empirical reports remain pending. Random networks, mock outputs or synthetic image software tests must never be reported as food-recognition accuracy. A later genuine evaluation report must identify the exact approved data/model, all manifests and limitations; negative results are acceptable.
